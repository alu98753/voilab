# Evaluate Model with Custom Features (Team 1 - AsiaDragon)

這份文件說明如何使用我們增強後的評估腳本 (`eval_kitchen.py`) 進行模型驗證。此評估流程包含多項我們自行開發的優化功能，旨在提高評估的準確性、可視化效果與管理效率。

## 🚀 快速啟動 (Quick Start)

使用 `uv run` 執行以下指令即可開始評估：

```bash
uv run voilab eval-model \
    --checkpoint data/outputs/2025.12.31/08.01.31_train_diffusion_unet_timm_umi/checkpoints/latest.ckpt \
    --output_dir data/eval_output \
    --task kitchen \
    --dataset_path ./AsiaDragon_1127_100/simulation_dataset.zarr.zip \
    --n_episodes 2 --headless
```

## 🔧 參數說明 (Inputs)

腳本支援兩個主要的執行模式：**重現模式** (預設) 與 **隨機模式**。

### 核心參數
- `--checkpoint` (Required): 訓練好的模型權重檔 (`.ckpt`)。
- `--output_dir` (Required): 評估結果的根目錄（腳本會自動在此目錄下建立結構化的子資料夾）。
- `--task` (Required): 任務名稱 (例如 `kitchen`, `dining-room`, `living-room`)。
- `--dataset_path` (Required if Mode 1): 原始模擬數據集 (`.zarr.zip`)。
  - **重要**: 用於讀取 Validation Index 和 `.previous_progress.json` 以確保重現性。
- `--n_episodes`: 要執行的評估回合數 (預設: 10)。
- `--headless`: 啟用無頭模式（不顯示 GUI，適合遠端執行）。

### 🧊 多樣化物件放置參數 (Diverse Object Placement Features)
該參數控制 Isaac Sim 中物體的初始狀態，是我們為提升 evaluation 多樣性所做的增強：

- `--random_poses`: **模式切換開關**。
    - **預設 (False)**: 使用 **Recorded Poses Mode**。從 `object_poses.json` 載入實際錄製的物體位置，確保評估環境與 Validation Set 完全一致。
    - **設為 True**: 使用 **Random Poses Mode**。在固定位置基礎上加入隨機擾動 (Jitter)，測試模型的泛化能力。

### 執行模式範例 (Run Modes)

#### Mode 1: Recorded Poses (默認/推薦)
加載訓練/驗證數據中使用的**精確初始物體位置**。這能最準確地評估模型在已知分佈上的表現。
```bash
python scripts/eval_kitchen.py --dataset_path {data_path}
```

#### Mode 2: Random Poses (泛化測試)
使用隨機擾動模式，測試模型對位置微小變化的魯棒性。
```bash
python scripts/eval_kitchen.py --random_poses
```

## 📂 輸出結果 (Outputs)

評估結果將自動根據 Checkpoint 的路徑進行分類，存放在 `output_dir` 下的結構化目錄中：

**路徑格式**：
`{output_dir}/{日期}/{訓練名稱}/{checkpoint名稱}/`

**包含檔案**：
1.  **評估日誌 (`eval_log.json`)**：詳盡記錄了每個 Episode 的成功與否、長度以及整體成功率。
2.  **腕部相機影片 (`eval_ep_{idx}.mp4`)**：機器人手腕視角的錄影。
3.  **前視角相機影片 (`eval_ep_{idx}_front.mp4`)**：我們新增的固定前視角錄影，提供更全面的觀察角度。

## ✨ 程式亮點 (Highlights) Note: Custom Implementation

此評估腳本包含多項 **Team 1 自行開發** 的功能優化 (非助教提供)，以解決模擬穩定性與資料一致性的問題：

### 1. 🎥 新增前視角相機 (Front Monitoring Camera)
我們在 Evaluation 環境中手動復刻了與 `generate_data.py` 一致的 `fixed_camera_front` 配置。
- **功能**：同步錄製並儲存前視角的 MP4 影片。
- **優勢**：能在腕部相機被遮擋時，提供額外的視覺資訊來分析失敗原因。

### 2. 🎲 多樣化物體放置 (Diverse Object Placement)
為了解決評估回合過於單一的問題，我們實作了與資料生成端同步的動態物體初始化：
- **技術細節 (IsaacSimRunner)**：
    - 在 `__init__` 中新增 `use_recorded_poses`, `object_poses_path` 與 `episode_indices` 接口。
    - 整合 `object_loader.py`，在 `run()` 循環中根據 Episode 索引即時從映射 JSON 獲取物體位姿。
- **物理穩定性優化**：
    - **位置鎖定**：修正了杯子容易傾倒的問題，僅更新 **Position** 而維持預設的 upright **Orientation**。
    - **物理沉降**：將 \"Settle Physics\" 邏輯對齊 `generate_data.py` (100-frame settle, `render=True`)，確保模擬物理極其穩定。

### 3. 🔄 智慧索引映射 (Smart Index Mapping)
我們發現 Zarr 數據集中的索引是連續的 (0, 1, 2...)，但實際上對應的可能是原始數據中的跳躍索引 (如 0, 1, 3, 5...)。
- **解決方案**：腳本會自動讀取 `.previous_progress.json`，將 Zarr 索引精確映射回原始的 `recorded episode index`。
- **效果**：確保評估時載入的 `object_poses.json` 位姿是完全正確的，實現真正的 Reproducibility。

### 4. 📂 自動化路徑管理 (Auto Path Structure)
為了解決評估結果散亂的問題，我們實作了自動路徑解析。
- **功能**：自動從 Checkpoint 路徑中提取日期與實驗名稱，建立層級分明的輸出目錄，讓實驗管理更井井有條。
